# A10 follow-up: npm dependencies and Ubuntu Ruby bundle

The Ubuntu candidate passes the high/critical image advisory gate. The npm audit
also passes that threshold. No scan exceptions or vulnerability suppressions were
introduced. This does not establish that the application has no vulnerabilities.

## Changes

- Updated fast-uri, ip-address, browserslist, js-yaml, linkify-it, nanoid and
  postcss through Socket within their existing dependency constraints.
- Updated markdownlint-cli2 from 0.22 to 0.23.2 to remove its exact dependency on
  vulnerable js-yaml 4.1.1. The root manifest records `^0.23.2` and the lock records
  the selected version. Remaining js-yaml consumers resolve a patched 4.x release.
- Kept the existing tar, brace-expansion and smol-toml security overrides.
- Replaced Ubuntu's unlocked OpenBolt gem installation with a frozen,
  checksum-bearing Gemfile.lock covering Linux amd64 and arm64.
- Migrated the WinRM FS archive constructor to RubyZip 3 named arguments and
  updated its RubyZip requirement. The source archive is checked against SHA-256
  before modification; the patched gem has local version `1.3.5.pabawi.1`.
  RubyZip is pinned to 3.6.0. OpenBolt remains at 5.1.0.

The upstream winrm-fs 1.3.5 release still requires RubyZip 2. Installing RubyZip 3
alongside it would not satisfy that dependency, and relaxing the requirement alone
would leave directory uploads failing at the positional `Zip::Entry` constructor.
The [bundle notes](../../docker/bolt/README.md) explain the local source patch,
upstream references, checks and retirement condition.

The WinRM regression uses the actual directory-upload preparation and checks
archive contents, binary data, empty files, hidden files, UTF-8 filename flags,
timestamps and upload digest/size metadata. A positive extraction round trip
passes, while a malicious archive cannot write into a sibling directory sharing
the destination prefix. These tests run during the Ubuntu build and were also
run inside the final non-root image. They do not contact a Windows host.

The image scan used the exported image archive, with the existing pinned Trivy
0.69.3 scanner. The image identity is:

`sha256:8c2b9dbd073626298153d598ef2959eb6800d8fcf853d7ec255b6fff8a085271`

Local SBOM, image metadata, vulnerability JSON and npm/Ruby dependency inventories
are retained in `/tmp/pabawi-a10-next-ubuntu-evidence/`. The source npm audit is
`/tmp/pabawi-a10-next-npm-audit.json`. CI retains its own JSON evidence and now
compares independent Ubuntu Ruby builds as well as npm installations.

## Remaining work

The release workflow still builds the default Bookworm Dockerfile. Its earlier
blocking findings are not cleared by the clean Ubuntu candidate. Bookworm and
Alpine were not rebuilt or rescanned in this follow-up. Their Ruby provisioning
also remains separate from the new Ubuntu bundle.

Distribution repositories remain mutable. A frozen Ruby lock fixes the Ubuntu
gem dependency graph, but does not establish full-image byte reproducibility.
The local image and repeat-build tests ran on arm64. The amd64 lock platform is
recorded, but amd64 execution and live Windows/WinRM interoperability have not
been verified in this follow-up. Nothing was published or deployed.

ClamAV 1.5.4 reported no infected files in the exported Ubuntu image (1.42 GiB
scanned) or the downloaded/resolved Ruby bundle (8,449 files).
The updated npm build dependencies also passed ClamAV: 35,849 files scanned,
with no infected files reported. These antivirus results do not clear the
remaining medium/low advisory findings.
